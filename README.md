# 证词 · Syllogism（零猜测骑士与无赖推理）

> *这一局没有格子，只有一叠口供。每一句都是一条方程：出货的每一局都在出厂前被铅笔求解器从空盘推过一遍，
> 唯一解由第二套不带任何推理的代码复核。*

浏览器原生的中文**骑士与无赖**推理：无构建步骤、无打包器、**零图片与音频文件**——卡堆、印鉴、空心框、
划掉的横线全部由 canvas 现画，音效由 WebAudio 合成，界面只有一个 `<canvas>` 加一列 DOM 面板。
**运行时依赖 0 个**（`electron` 只出现在 devDependencies，CI 连 `npm install` 都不跑）。

规则只有一条：每个人非骑士即无赖，骑士句句为真、无赖句句为假，所以**每一条证词恰好写成**

```
说话人是骑士  ⇔  他说的这句命题为真
```

全盘 n 个人、若干句话，解就是所有人的身份。没有"看起来像好人"，也没有运气题。

- **核心承诺 1｜零猜测**：出货的每一局都能**只用七条铅笔规则从空盘推到底**。这不是文案，是准入门槛——
  `solvableByPencil()` 推不到底的候选盘直接丢弃，低三档连反证都不许用。
  证明它：`npm test`（逐档断言「提示通道能从空盘推完」）· `npm run balance`（200 局从空盘复推一致）。
- **核心承诺 2｜唯一解**：`count.js` 是一台**不带任何推理逻辑**的 2^n 真值表计数器，
  它和铅笔求解器从两个方向回答同一个问题；两者不一致的盘不出货。
  证明它：`npm run balance` 末行 `200/200 局穷举复核、复解分数与证词合法性全部一致`。
- **核心承诺 3｜提示不是答案**：提示走的是**同一个** `nextDeduction()`，所以它必须点名用了哪条规则、
  钉住哪一个人；推不出东西时它不收钱，只说"此刻推不出新的那个人"。
  证明它：`npm test`（提示文本必须含人名，且严格长于"甲 是骑士"这句光杆答案，否则记 `提示只是答案`）·
  `npm run verify` 的 `hint` 场景（五档各一局，逐条核对提示给的值就是真解）。
- **核心承诺 4｜存档只记你欠了多少**：撤销一步**不退**求助次数，纪录按 `提示 → 步数 → 时间` 排，
  续局连"这一局吃了几次提示"一起存。
  证明它：`npm run verify` 的 `hint` + `save` 场景（含"更快但求助更多的不算破纪录"逐条断言）。
- 难度不是标签：`见习 → 大师` 五档的分数带由求解器**实测**得出（`npm run balance` 打印分位表），
  `TIERS` 里的 `band` 是**选取目标**——每档一直抽题，直到分数落进自己的区间，`balance` 再盯着这件事不许漂移。
- 局由种子寻址：整叠口供在客户端现生成，毫秒级，所以存档里**没有题面、也没有答案**，只有一颗种子和这一局的成本。
- 规模：10 个 ES Module / 约 3,100 行 JS + 5 个验证脚本 / 约 2,100 行 + 583 行 CSS/HTML。
- **在线试玩**：<https://z-biz-game.github.io/z-biz-game-syllogism-cos/>（`main` 分支推送即自动部署）

```bash
npm run dev          # 本项目专用端口 5261

```

```bash
npm run check        # 逐文件 node --check 语法门禁
npm test             # 引擎断言 150 项：手写盘的期望值 / 四个计数判定 / 两张权重表同序 /
                     # 五档出货·唯一解·提示能推完 / 生成纯函数与 chainWidth 两条回归

```

`npm run verify` 自己起服务、自己开 Chrome、自己收尾，退出码即结论；它会先核验端口上 serve 的
确实是本应用（`index.html` 里必须同时出现「证词」和 `Syllogism`），否则直接拒绝开跑。十个场景：

```
engine   引擎口径与手写期望          gen      五档出货 / 唯一解 / 规模
play     落子·收回·拖拽取消·判胜     hint     提示计费与"不是答案"
save     存档形状与纪录排序          resume   由种子重建同一间房
layout   槽位往返、命中区互不重叠    input    鼠标/触摸/键盘改的是同一个状态
real     Chrome 自己的输入队列（可信事件）      fit   420×900 真手机视口
```

同一套断言可以直接打线上产物，部署过没部署过不是一句声明：

```bash
BASE_URL=https://z-biz-game.github.io/z-biz-game-syllogism-cos/ npm run verify
```

## 玩法

| 操作 | 行为 |
|---|---|
| 点卡头上的**骑士 / 无赖**牌 | 落下这个人的身份。一个人只持一个三态值，写一个**就是**擦掉另一个 |
| 再点同一张牌 | 收回未定——同一条规则同时管两种手势，不用记两套操作 |
| 点在卡面正文或人名上 | 焦点移到这个人：`kind:'card'` 的槽位在 `commitSlot()` 里直接返回 `null`，**不落子、不预览、不记账** |
| 点句首的小方格 | 划掉这一句（自己的笔记）：记进撤销账本、可撤销，但**不涨步数** |
| 起手在牌上、松手在别处 | 那是拖拽不是决定：整笔取消，账本不动 |
| `↑↓` 换人 · `Tab` `←→` 沿焦点路径逐句走 | 键盘走的是同一个 `writeForSlot`，三种输入不可能分家 |
| `1` `2` `3` / `Enter` `空格` / `.` | 骑士 / 无赖 / 未定 · 三态轮换 · 划掉当前这句 |
| `H` / `U` / `R` / `P` / `Esc` | 提示 / 撤销 / 重开 / 暂停 / 回选档 |

规则口径（写错任何一条，整盘判断都会崩）。前三条在 `tools/engine-test.mjs` 里有**手写盘的期望值**兜着，
第四条由五档出货断言兜着（`出货规模全部合规（人数/最少句数/至少一骑士一赖）`），第五条在浏览器场景里：

1. 一条证词的方程是 `说话人=骑士 ⇔ 那句为真`；说话人是无赖时，**整句**取假（复合句也是整体取反，不是逐小句取反）；
2. 自指合法，而且是最锋利的一类线索：甲说「我和乙同类」⇒ **乙必是骑士**，甲自己两个值都活着；
3. 恒真或恒假的证词不许出现在盘上（`validStatement()`）——它对"谁是谁"没有任何约束，白送难度分；
4. 每局至少一个骑士、至少一个无赖：全员同身份的题读起来像陷阱，而且会让「恰好 k 个骑士」退化成一句话；
5. 划掉的句子是玩家自己的笔记，对推理**完全透明**——引擎从来不知道它被划过，划一下也不改变任何方程。

七条铅笔规则：`直接身份` · `关系锁定` · `联立真值表` · `计数钉死` · `复合拆开` · `自指消去` · `反证`。
提示只会说这七个名字——它们定义在 `Rules`、在 `RuleGloss` 里逐条解释，选档页就是把后者原样列出来，
场景断言两边都正好七个（名单分家当场可见）。

## 五档，量出来的

`npm run balance`（每档 40 局）打印的实测结果，`TIERS` 的 `band` 就照这张表写：

| 档 | 人数 | 联立宽 | band（选取目标） | 分数 p25/中位/p75/max | 命中率 | 平均尝试 | ms/局 |
|---|---|---|---|---|---|---|---|
| 见习 | 3 | 2 句 | [8, 9] | 8.5 / 8.5 / 8.8 / 8.8 | 40/40 | 1.9 | 0.3 |
| 熟练 | 4 | 3 句 | [9, 15] | 14.5 / 14.8 / 14.8 / 14.9 | 40/40 | 4.8 | 1.1 |
| 老手 | 5 | 3 句 | [15, 19] | 16.6 / 17.5 / 18.5 / 18.8 | 40/40 | 3.0 | 1.1 |
| 专家 | 6 | 3 句 | [19, 29] | 21.5 / 27.6 / 28.2 / 29.0 | 40/40 | 2.2 | 5.8 |
| 大师 | 7 | 3 句 | [29, 34] | 30.1 / 30.8 / 31.1 / 32.2 | 40/40 | 2.2 | 8.8 |

- 五段区间**相邻且不重叠**（`npm test` 逐字断言整张 band 表与这条性质）；**中位数单调不减**是
  `npm run balance` 的门禁，不达标就 exit 1。
- `反证` 只出现在专家（中位 4 次）与大师（中位 6 次）；低三档 120 局里一次都没有——
  "这一档不给玩家用这一手"既是准入门槛也是承诺，`balance` 有一道门禁专门盯着它。
- 阶梯最贵的一格是**结构**造出来的：大师的下界 29 压在专家**不做选取时**的实测分位（中位 22.7 / p75 27.9 / max 29.6）
  之上。也就是说，两档的分离不是挑选挑出来的花样——随机抽到的专家盘本来就够不到 29。
- 出题耗时毫秒级（最慢档位个位数 ms，每盘平均抽 1.9–4.8 次）。`ms` 那一列**只是这台机器的读数**：同命令复跑
  最慢档位读到过 6.2 / 7.9 / 8.8 ms，它不进任何断言。分数列不同——样本种子写死在 `balance|0 … balance|39`
  （`SAMPLES=` 可改样本数），只要 `grade()` 与生成器不动，任何机器复跑都该逐字相同。
- 抽题次数是区间选取的代价，不是失败率：五档命中率都是 40/40。
- 相邻档共享端点（专家上限 29、大师下限 29），所以**单样本可以合法打平**；被断言的是可检验的那两条：
  区间本身递增、四局以上中位数不下降。

## 验证在验证什么

`tools/scenarios.js` 的口径是：读 **DOM 几何 / DOM 文本 / canvas 像素**，不读 JS 里的 `.hidden` 标志位——
"看得见"一律问 `getComputedStyle().display` 与 `getClientRects()`，而不是问那个布尔值。
状态对而画面错、状态对而点击差一张卡，是这个游戏真正会犯的错，而标志位看不见它。举几条：

- 槽位逐个往返：渲染器认为某张牌在哪个点，命中测试就必须把那个点还回同一个槽（全部槽位，不只抽样）。
- 命中区**两两不重叠**：一次点击只能意味着一件事。
- 留白不属于棋盘：`pad` 上和画布外的点都返回 `-1`，既不落子也不记账。
- 骑士牌与无赖牌**不同形**、未定牌明显更小，三态在像素层面可分（比较暖/冷/墨的比例，不是绝对阈值）——
  去掉颜色也读得出身份，这是牌面的硬要求。
- 证词正文真的被画出来了（数该区域的亮像素），划掉之后该区域像素必须变，撤销之后必须逐像素回到原样。
- 非法满盘（全员骑士，很亮但不合法）不判胜；冲突读数与冲突行同时跟上；此时提示只报矛盾、**不收费**。
- 图例上写「不算落子」，账本就必须不收费：断言直接读图例文案来决定 `moves` 该不该涨——
  屏幕上承诺的规则和记的账分家，就是在这里失败。
- 提示改不掉的东西：五档各一局，一路只吃提示也能清空棋盘，且每一次落子的值都等于真解。
- 撤销提示**不退**求助次数，也不退步数（它本来就不是步）；重复讨要同一处推论必须给新东西。
- 存档里没有题面、没有规则表、没有答案，玩家落的身份只以游程对留下：
  续局由种子重建，逐句比对重建后的口供与原局相同；
  续局部分实测 < 320 字节，整个存档 < 1000 字节。
- 三种输入（鼠标 / 触摸 / 键盘）落的是同一步、记的是同一笔账；`real` 场景走 Chrome 自己的输入队列，
  因为"可信事件"正是合成事件最容易蒙过去的那一条。
- 420×900 真手机视口下：整叠口供一屏看全、主操作键在首屏内、横向不滚动，
  且页面上**没有任何一处文字小于 14 px**（DOM 与 canvas 两侧分别断言）。

## 部署

`main` 分支推送 → `.github/workflows/pages.yml` 把 `index.html` + `css` + `js` 复制成静态站点
（无打包器，也就不用打包器），再发布到 Pages。

Pages 要先在仓库设置里开启并把构建方式设为 `workflow`（`POST /repos/{org}/{repo}/pages`
带 `{"build_type": "workflow"}`，或 Settings → Pages → Source: GitHub Actions）。
`actions/deploy-pages` 只部署"Pages 已由 Actions 构建"这个事实，源没开时它直接失败——
推送本身不会替你打开它。线上地址即仓库的 homepage。

`.github/workflows/ci.yml` **连 `npm install` 都不跑**（没有依赖可装，把桌面壳拉进 CI 只会让一次网络抖动
变成一次红灯）。它做三件事：逐文件 `node --check`、跑 `tools/engine-test.mjs` 那 150 项断言、确认
`index.html` 里确实挂着那个 canvas 和 `js/main.js`。引擎的三条承诺（零猜测 / 唯一解 / 提示不是答案）
就在这一步里被守住——没有浏览器也一样。难度实测台与浏览器场景不在 CI 里：前者是每次动到评分就要人
手工跑一遍的量表，后者需要本机 Chrome。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`29`）与这一次跑的断言条数（`47`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`29`、断言仍然 `47`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；把它们接进本仓
那条浏览器 one-shot（`tools/verify.sh`）还欠着——那道脚本的腿名单与条数钉是每个仓自己的形状。
